    silently. FIX: Remove the first pass entirely.

[x] BUG-002: CRITICAL — Audit-to-proposal join via code string matching
    audit.py joins PipelineSkillsLedger to Proposal via
    transformation_script_ref == generated_code. This is unreliable.
    FIX: Add proposal_id FK to PipelineSkillsLedger model.

[x] BUG-003: CRITICAL — No proposal_id on PipelineSkillsLedger
    Makes audit -> proposal linking fragile. Must add proposal_id column.

[x] BUG-004: MEDIUM — GET /proposals/{id} re-reads CSV from /tmp
    proposals.py line 21 does pd.read_csv(proposal.file_path) just to get
    row count. If /tmp is cleaned, this crashes.
    FIX: Store estimated_rows on Proposal model.

[x] BUG-005: MEDIUM — pii_columns_found always [] on GET proposal
    proposals.py line 30 hardcodes empty list.
    FIX: Store pii_columns_found on Proposal model.

[x] BUG-006: LOW — Wrong LLM version string hardcoded
    execution_service.py line 122 says "llama-3.1-70b-versatile" but actual
    model is "llama-3.3-70b-versatile". Also hardcoded in proposals.py.
    FIX: Store llm_model_used on Proposal model and reference it.

[x] BUG-007: LOW — SQL injection risk in mcp_service.py
    get_data_distribution() uses f-strings for table_name and column_name
    in SQL queries (lines 73-88).
    FIX: Use parameterized queries or at least whitelist table names.

[x] BUG-008: MEDIUM — No error handling around AI call in ingest
    If Groq API fails, pandas fails, or file save fails, raw 500 error.
    FIX: Add try/except with proper HTTPException responses.

[x] BUG-009: LOW — Mock AI generated_code has "import hashlib" inside
    function body. System prompt says "Import nothing inside the function"
    but mock code contradicts this. Not caught by validation since hashlib
    isn't in the blocklist, but inconsistent.
